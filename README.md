# Restful Booker API tests

Postman-коллекция для тестового REST API [Restful Booker](https://restful-booker.herokuapp.com/). Коллекция содержит 12 последовательных запросов и 26 автоматических проверок ответа.

## Запуск

### Postman

1. Импортируйте `restful-booker.postman_collection.json` через **Import → Files**.
2. Запустите коллекцию через **Run** в исходном порядке.
3. Если тестовый стенд сменил демонстрационные учетные данные, поменяйте `username` и `password` в переменных коллекции.

Коллекция сама получает токен, генерирует данные, сохраняет ID созданной брони, передает их в следующие запросы и удаляет запись в конце. Окружение Postman не требуется.

### Newman

Нужны Node.js и pnpm. В корне проекта выполните:

```bash
pnpm install --frozen-lockfile
pnpm test:api
```

Или без установки проекта:

```bash
npx --yes newman@6.2.1 run restful-booker.postman_collection.json
```

## Сценарии и ожидаемые результаты

1. `POST /auth` — `200`, JSON и непустой строковый токен сохраняются в переменную коллекции.
2. `GET /booking` — `200`, JSON-массив; ID каждой записи — число.
3. `POST /booking` — `200`, возвращается числовой `bookingid`, обязательные поля имеют ожидаемые типы и значения. Граничные данные: цена `0`, пустой `additionalneeds`.
4. `GET /booking/:id` — `200`, обязательные поля присутствуют, цена числовая, даты соответствуют `YYYY-MM-DD`.
5. `PUT /booking/:id` с датой `not-a-date` — стенд отвечает `200` и возвращает испорченную дату вместо отказа. Это проверка известного дефекта валидации, а не корректное поведение API.
6. `PUT /booking/:id` без токена — `403`.
7. `PUT /booking/:id` с токеном — `200`; цена меняется на `1`, `depositpaid` на `false`, дата восстанавливается в допустимый формат.
8. `GET /booking/not-a-number` и `GET /booking/0` — `404`.
9. `POST /booking` без обязательного `firstname` — стенд отвечает `500`. Тест фиксирует наблюдаемое поведение; корректный API должен возвращать контролируемую ошибку валидации.
10. `DELETE /booking/:id` — `201`; повторный `GET` этой записи — `404`.

Публичный демо-сервис может быть нестабилен или менять данные. Набор проверок рассчитан на его текущий контракт; известные недостатки стенда описаны явно.

## CI

GitHub Actions запускает коллекцию Newman на `push`, `pull_request` и вручную через **Actions → Newman API tests → Run workflow**. Доступность внешнего демо API необходима для успешного прогона.
